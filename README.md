# MemHunter

Быстрый поиск строк, байтовых шаблонов и сигнатур в памяти процессов Windows, снапшоты памяти с
последующим сравнением, полноэкранный терминальный интерфейс и графическое окно. C++20, CMake, GoogleTest,
Dear ImGui.

## Назначение и границы

MemHunter предназначен для диагностики, отладки и анализа процессов, к которым у пользователя есть
законный доступ. Процесс открывается обычным `OpenProcess` с правами
`PROCESS_QUERY_INFORMATION | PROCESS_VM_READ | SYNCHRONIZE` от имени текущего пользователя. Если Windows отказывает в доступе, MemHunter сообщает об этом и завершается
с кодом 3. Он не повышает привилегии, не включает `SeDebugPrivilege`, не внедряет код, не пишет в чужую
память, не обходит механизмы защиты и не трогает guard-страницы.

Права MemHunter наследует от окна, из которого его запустили. Если в этом окне `SeDebugPrivilege` уже
включена (так бывает в некоторых окнах администратора, проверка: `whoami /priv`), Windows открывает такому
процессу почти любой процесс независимо от прав доступа.

Потренироваться можно на отдельной цели с понятными данными и включаемыми защитами:
[practice/README.md](practice/README.md).

## Сборка

Нужны Windows 10 1607+ (x64), CMake ≥ 3.24, Ninja и компилятор C++20. Проверялся только MinGW-w64 GCC 16.2.0.
Для MSVC в `CMakeLists.txt` есть флаги, но сборка с MSVC не проверялась.

Портативный набор инструментов, на котором всё собрано и проверено, лежит в `C:\Users\MorrTry\tools`:
`cmake-4.4.4-windows-x86_64`, `mingw64` (GCC 16.2.0) и `ninja`.

```sh
export PATH="/c/Users/MorrTry/tools/cmake-4.4.4-windows-x86_64/bin:/c/Users/MorrTry/tools/mingw64/bin:/c/Users/MorrTry/tools/ninja:$PATH"
cmake --preset release            # build/release, Ninja, Release
cmake --build build/release
cd build/release && ctest --output-on-failure -j 8
```

GoogleTest ≥ 1.14 берётся из системы (`find_package`). Если его нет, CMake скачивает v1.17.0 через
`FetchContent`, и для этого при первой конфигурации нужен интернет.
Исполняемые файлы линкуются статически и зависят только от системных DLL:

| Файл | Что это |
|---|---|
| `build/release/src/memhunter.exe` | сам инструмент (командная строка и TUI) |
| `build/release/src/memhunter_gui.exe` | графический интерфейс, см. [ниже](#графический-интерфейс) |
| `build/release/tests/memhunter_tests.exe` | модульные и интеграционные тесты |
| `build/release/tests/memhunter_test_target.exe` | отдельный тестовый процесс-мишень, в котором тесты ищут известные данные |
| `build/release/bench/memhunter_bench.exe` | бенчмарки, см. [bench/README.md](bench/README.md) |
| `build/release/practice/memhunter_practice.exe` | тренировочная цель, см. [practice/README.md](practice/README.md) |

Опции CMake: `MEMHUNTER_BUILD_TESTS` (ON), `MEMHUNTER_BUILD_BENCH` (ON; бенчмарку нужен тестовый процесс),
`MEMHUNTER_BUILD_PRACTICE` (ON) и `MEMHUNTER_BUILD_GUI` (ON). Для GUI при первой конфигурации CMake скачивает
Dear ImGui v1.91.9b (`FetchContent`, архив проверяется по SHA-256), поэтому нужен интернет. С
`-DMEMHUNTER_BUILD_GUI=OFF` всё остальное собирается без него.

## Графический интерфейс

`memhunter_gui.exe` — обычное окно Windows (Dear ImGui, Direct3D 11), открывается двойным щелчком. Без
аргумента сразу предлагает выбрать процесс; можно передать PID или имя: `memhunter_gui.exe memhunter_practice.exe`.

| Область | Что показывает |
|---|---|
| верхняя строка | процесс, PID и разрядность, состояние, кнопки «Выбрать процесс» и «Экспорт» |
| поиск | режимы Текст / Байты / Число / Строки, кодировка, типы памяти, сравнение, потоки и лимит совпадений |
| прогресс | этап и процент, прочитано байт, регионы, совпадения |
| результаты | таблица с сортировкой и фильтром: адрес, тип, шаблон, длина, защита, память, модуль, превью hex или текст; вкладка «Регионы» показывает карту памяти процесса, вкладка «Адреса» — список адресов, вкладка «Указатели» — цепочки указателей, вкладка «Структура» — поля структуры |
| подробности | совпадение или адрес из списка, его регион и память вокруг (160 байт, нужные байты выделены инверсией, обновляется дважды в секунду) |
| строка статуса | скорость, ошибки чтения, время, потоки, алгоритм, подсказка по клавишам |

- **Число (поиск значений, как first/next scan в Cheat Engine):** int8/16/32/64, float, double.
  - Первый поиск: «Равно», «Больше», «Меньше», «Между» или «Неизвестное начальное значение» (запоминает все
    значения выбранного типа). Под полем видно, какими байтами число лежит в памяти (15000 как int32 —
    `98 3A 00 00`).
  - «Следующий поиск» перепроверяет только найденные адреса. К сравнениям с числом добавляются
    «Увеличилось», «Уменьшилось», «Изменилось» и «Не изменилось» — относительно прошлого поиска.
    «Новый поиск» забывает адреса.
  - История: под кнопками перечислены все поиски с условием и числом адресов (`1  int32 = 86  108`,
    `2  = 73  1`). Щелчок по строке, Ctrl+Z и Ctrl+Y возвращают к нужному шагу, в том числе к его колонке
    «Было». Следующий поиск из отменённого шага заменяет шаги после него. Вся история занимает не больше
    памяти, чем разрешено первому поиску; если не хватает, удаляются самые ранние шаги.
  - Таблица: адрес, «Сейчас» (перечитывается дважды в секунду, изменившееся значение в рамке), «Было»
    (при прошлом поиске), защита, тип памяти, модуль. Показаны первые 10 000 адресов, считаются все.
  - Целые сравниваются как знаковые; «Равно» находит и беззнаковую запись (4294967295 = −1). Float сравнивается
    с точностью введённого числа: «100» — это от 99.5 до 100.5, «99,5» — от 99.45 до 99.55.
  - «Только выровненные адреса» (по умолчанию) проверяет адреса, кратные размеру типа.
  - Список адресов хранится плотно (битовая карта и байты) и разрежается по мере сужения. Если для первого
    поиска нужно больше трети свободной памяти, поиск останавливается и просит сузить условия.
- **Список адресов (вкладка «Адреса»):** адреса, за которыми нужно следить.
  - Добавить: правый щелчок по результату → «В список адресов» или клавиша Insert. Число попадает со своим
    типом, текст — как ASCII или UTF-16, сигнатура — как байты длиной совпадения. Кнопка «Добавить
    адрес…» принимает адрес вручную (`0x7FF6A0001000`). Повтор не добавляется, выделяется уже имеющаяся строка.
  - Типы: int8/16/32/64, float, double, текст ASCII и UTF-16 и байты длиной до 256 байт.
  - Колонки: описание, адрес, тип, значение, модуль. Значения перечитываются дважды в секунду, изменившееся
    за последние 2 секунды — в рамке, `??` — память не читается.
  - Описание меняется двойным щелчком или F2, тип и длина — в панели подробностей. Del удаляет строку,
    «Очистить» после подтверждения убирает весь список, Ctrl+C копирует адрес, Ctrl+S сохраняет список
    с текущими значениями в JSON, CSV или текст.
  - Список относится к процессу: при повторном подключении к тому же запуску он остаётся. При выборе
    другого процесса обычные адреса удаляются, а записи-цепочки остаются, если имя exe то же: их адрес
    вычисляется заново. Значения только читаются — записи и заморозки нет.
  - В экспорте у записей-цепочек заполнена колонка `pointer` (`[[game.exe+0x1A2B0]+0x10]+0x8`).
- **Указатели (вкладка «Указатели»):** цепочки указателей от модуля к адресу. Цепочка позволяет найти
  значение снова после перезапуска программы, когда объект оказывается по другому адресу.
  - Поиск: выберите запись на вкладке «Адреса» и нажмите «Найти указатели…». Глубина — до 7 указателей
    (по умолчанию 5), «Смещение до» — наибольшее смещение, прибавляемое к указателю (по умолчанию 0x1000).
    Поиск идёт в фоне с прогрессом по этапам и останавливается по Esc.
  - Указатели читаются из записываемой памяти всех типов, цепочки начинаются в образе модуля
    (`game.exe+0x1A2B0`). Сначала идут короткие цепочки; в списке хранится не больше 1 000 000. Если поиску
    нужно больше трети свободной памяти, он останавливается и просит уменьшить глубину или смещение.
  - Таблица: база, смещения, адрес, куда цепочка ведёт сейчас, и значение там (`??` — указатель по пути не
    читается). Значения перечитываются дважды в секунду.
  - «Проверить…» после перезапуска программы: найдите значение заново и оставьте цепочки, которые ведут к
    новому адресу, или (для чисел) цепочки, значение по которым сейчас равно введённому. Если не подходит ни
    одна, список не меняется.
  - «В список адресов» (двойной щелчок, Insert или меню) добавляет цепочку как запись, адрес которой
    вычисляется при каждом обновлении. Ctrl+C копирует цепочку.
  - «Сохранить…» и «Загрузить…» — файл `.mhp` (пишется через `.partial`, защищён XXH64), его же читает
    `memhunter pointers`.
- **Структура (вкладка «Структура», как Dissect data/structures в Cheat Engine):** память вокруг адреса,
  разобранная на поля.
  - Открыть: на вкладке «Адреса», «Указатели» или «Результаты» выберите строку и нажмите Ctrl+D (или
    «Разобрать структуру…» в меню правой кнопки, или «Структура…» на вкладке «Адреса»). Ещё можно нажать «Открыть…»
    на вкладке «Структура». База — адрес (`0x1F4A2C3B0D8`) или цепочка (`[[game.exe+0x52080]+0x8]`), размер —
    до 0x10000 байт (по умолчанию 0x200). Для записи-цепочки база — цепочка без последнего смещения, а само
    поле выделено: здоровье `[[game.exe+0x52080]+0x8]+0x50` откроется как структура
    `[[game.exe+0x52080]+0x8]` с выделенной строкой 0x50.
  - Таблица: смещение, тип, имя, значение. Значения перечитываются дважды в секунду, изменившееся за
    последние 2 секунды — в рамке, `??` — память не читается. Цепочка проходится заново при каждом
    чтении, поэтому структура находится и после того, как программа её переложит. При выборе
    перезапущенного процесса с тем же именем exe структура по цепочке остаётся, по обычному адресу —
    закрывается.
  - Типы угадываются по байтам: указатель в читаемую память (с `game.exe+0x…`, если он ведёт в модуль),
    текст ASCII и UTF-16, double, float, int32. Нули подряд показываются одной строкой (`00 × 16`).
    int64 не угадывается: такое поле видно как два int32, пока его не задать.
  - Задать поле: F2, двойной щелчок или «Изменить…» — смещение, тип (int8/16/32/64, float, double,
    pointer, ASCII, UTF-16, байты), длина и имя. Del или «Сбросить» снова отдаёт поле угадыванию.
    «Угадать заново» переугадывает незаданные поля по тому, что в них сейчас.
  - Указатель раскрывается → (или Enter) и сворачивается ←: под ним появляются 0x100 байт структуры, куда
    он ведёт, до 7 уровней. «Разобрать отсюда» делает эту структуру главной, а база становится длиннее на
    одно смещение.
  - «Сравнить…» добавляет ту же структуру по другому адресу или цепочке — до 4 столбцов «Значение». Значения,
    которые отличаются от первого столбца, инвертированы. Так видно, какие поля у двух игроков общие.
  - Insert или «В список адресов» добавляет поле на вкладку «Адреса» (из структуры по цепочке — как
    запись-цепочку). Ctrl+C копирует цепочку или адрес поля, «Как C» — объявление `struct` на C.
  - Ctrl+S или «Сохранить…» записывает заданные поля в файл `.mhst` (строки `size 0x200` и
    `0x50 int32 health`), «Загрузить…» накладывает поля из файла на открытую структуру. Этот же файл читает
    `memhunter struct --def`.
- **Сравнение:** «Запомнить память» хеширует выбранную память. После того как значение в программе
  изменилось, поиск с отметкой «Только изменившаяся память» проверяет только изменившиеся блоки. Так из
  многих одинаковых чисел остаётся нужное. Сравнение работает в пределах одного запуска процесса.
- **Клавиши:** F5 или Enter — найти, Esc — остановить, Ctrl+F — фильтр, Ctrl+O — выбор процесса,
  Ctrl+S — экспорт (на вкладке «Указатели» — сохранение цепочек, на вкладке «Структура» — сохранение полей),
  ↑ ↓ PgUp PgDn Home End — по таблице, Ctrl+C — скопировать адрес, Insert — в список адресов, Ctrl+D —
  разобрать структуру вокруг выбранного адреса. На вкладке «Структура»: F2 — изменить поле, Del — сбросить
  его к угаданному, → ← — раскрыть и свернуть указатель. Правый щелчок по строке открывает меню копирования
  адреса, байтов и текста.
- **Экспорт:** JSON, CSV или текст, формат по расширению файла.
- **Тема:** чёрно-белая. Фон `#000000`; текст, рамки и кнопки `#FFFFFF`; выделение и активный пункт
  показаны инверсией. Серым приглушены только подсказки и недоступные элементы. Цвета собраны в
  `src/gui/theme.*` отдельно от логики.
- **Права:** окно получает права того, кто его запустил. При запуске двойным щелчком процессы
  администратора не открываются, для них MemHunter нужно запустить от имени администратора. Защищённые
  системные процессы (например, `csrss.exe`) не открываются ни так, ни так. Интерфейс объясняет причину.
- **Только чтение:** GUI использует то же ядро, что и `memhunter`, и в чужую память не пишет.

## Команды

Полная справка выводится командой `memhunter help <команда>`. Процесс задаётся PID или именем
(`notepad.exe`). Если процессов с таким именем несколько, MemHunter просит указать PID.

### scan: поиск за один проход по памяти

```sh
memhunter scan 1234 --string "config.json" --string "https://"      # ASCII/UTF-8 и UTF-16LE
memhunter scan 1234 --pattern "48 8B ?? ?? 90" --pattern "jmp=E9 4? ?? ?? ??"
memhunter scan 1234 --pattern-file sigs.txt --protection executable --include "game*.dll"
memhunter scan 1234 --strings --min-length 8 --unicode --format json --output strings.json
memhunter scan 1234 -s password -i --type private --grep admin --sort region
```

- Шаблоны:
  - `--string`: литерал в ASCII и/или UTF-16LE (`--ascii`, `--unicode`, `--encoding`); `-i` включает поиск без учёта регистра ASCII.
  - `--pattern`: сигнатура с `??` и полубайтовыми масками (`4?`, `?F`).
  - `--pattern-file`: по одной сигнатуре на строку.
  - `--strings`: извлечение печатаемых строк.
- Какая память читается: по умолчанию все committed-регионы, доступные для чтения, любого типа.
  Страницы `PAGE_GUARD` и `PAGE_NOACCESS` пропускаются. Фильтры: `--protection`, `--type`,
  `--min/max-region-size`, `--include`/`--exclude` (диапазон адресов или glob модуля/файла).
- Движок:
  - Рабочие потоки (`-j`) и потоки чтения (`--readers`) обмениваются данными через ограниченную очередь.
  - Размер блока (`--chunk-size`, по умолчанию 256 KiB) и алгоритм (`--algorithm`).
  - Каждый блок читается с запасом на длину шаблона, а совпадение засчитывается блоку, в котором оно
    начинается. Поэтому совпадения на стыке блоков не теряются и не дублируются.
- Вывод:
  - Форматы: text, json или csv.
  - Сортировка, `--limit`, фильтры по виду, шаблону, диапазону адресов и тексту превью.
  - Каждое совпадение несёт регион, модуль и защиту.
- Ctrl+C останавливает поиск и выводит найденное к этому моменту (код 5).

### regions и ps

```sh
memhunter regions 1234 --type image --format csv     # регионы, которые прочитает scan
memhunter regions 1234 --all                         # включая reserved и недоступные
memhunter regions 1234 --all --type private          # с --all остальные фильтры действуют, кроме --protection
memhunter ps "chrome*"                               # список процессов
```

### snapshot, diff, info: снапшоты и сравнение

```sh
memhunter snapshot 1234 -o before.mhs                 # таблица регионов + хеши блоков, без содержимого
memhunter snapshot 1234 -o full.mhs --with-data       # плюс содержимое памяти (большой файл)
memhunter info before.mhs                             # что именно сохранено в файле
memhunter diff 1234 before.mhs                        # снапшот против живого процесса
memhunter diff 1234 before.mhs after.mhs              # два снапшота; PID проверяет, что оба сняты с текущего запуска
memhunter diff before.mhs after.mhs --show all --format json
memhunter scan 1234 --strings --changed-since before.mhs   # инкрементальный повторный поиск
```

- **Что сохраняется:**
  - По умолчанию сохраняются только метаданные:
    - таблица регионов (адрес, размер, состояние, защита, тип, модуль);
    - захваченные диапазоны;
    - 64-битный хеш XXH64 каждого блока (`--block-size`, 4 KiB–1 MiB, по умолчанию 4 KiB).
  - Такой снапшот показывает, *изменился ли* блок, но не *что в нём было*. `info` и `diff` прямо пишут
    «hashes only» и не выдают его за дамп памяти.
- **Полный снимок** (`--with-data`) включается только явно:
  - Перед записью печатается оценка размера и предупреждение, что в файл попадёт сырая память (возможно,
    пароли и ключи).
  - Выборка больше `--max-data` (по умолчанию 1 GiB) отклоняется.
  - Если на диске мало места, MemHunter заранее отказывается писать (код 4).
- **Сравнение:**
  - Отчёт содержит добавленные, удалённые и изменённые регионы.
  - Память делится на диапазоны `changed`, `unchanged`, `unknown` (не читалась на одной из сторон),
    `added` и `removed`.
  - Без содержимого точность ограничена блоком; если содержимое есть с обеих сторон, точность до байта.
- **Совместимость:**
  - Снапшоты с разными размерами блоков или страниц не сравниваются (код 6).
  - Снапшоты разных запусков процесса отклоняются. Запуск определяется по PID и времени создания процесса;
    Windows переиспользует и рандомизирует адреса (ASLR), поэтому одинаковые адреса в разных запусках
    могут хранить несвязанные данные.
  - `--force` всё же сравнивает такие снапшоты и помечает отчёт.
- **`--changed-since`:** память всё равно читается целиком, чтобы посчитать хеши, но ищется только в
  изменившихся и новых блоках. Выводятся совпадения, пересекающие такие блоки.

#### Формат файла (версия 1)

Все числа в формате little-endian. Файл состоит из трёх частей:

1. Заголовок, 64 байта:
   - сигнатура `MHSNAP\x1A\n`, версия формата, флаги;
   - смещения и размеры секций;
   - хеш метаданных и хеш самого заголовка.
2. Содержимое блоков. Есть только при флаге contents (`--with-data`).
3. Метаданные:
   - размеры страницы и блока, время снимка, идентичность процесса (PID, имя, путь, время создания, разрядность);
   - таблица регионов, диапазоны;
   - состояние и хеш каждого блока.

Каждый байт покрыт хешем: заголовок и метаданные напрямую, содержимое блоков через хеши блоков.

- Файл сначала пишется как `FILE.partial` и переименовывается только после успешного завершения.
- Обрезанный, испорченный, неизвестный или более новый файл даёт понятную ошибку и код 6.
  Тесты проверяют:
  - испорченные байты заголовка, метаданных и содержимого;
  - обрезанный файл и файл с лишними байтами;
  - пустой и чужой файл;
  - более новую версию формата.

### value: поиск числа по шагам

```sh
memhunter value game.exe --eq 100 --save hp.mhv     # первый поиск: адреса со значением 100
memhunter value hp.mhv --decreased                  # значение уменьшилось; hp.mhv заменяется оставшимися адресами
memhunter value hp.mhv --eq 73                      # следующий поиск с точным значением
memhunter value hp.mhv                              # показать сохранённые адреса и их текущие значения
memhunter value game.exe --unknown --as float --type private --save speed.mhv
```

Как в GUI, только состояние поиска хранится в явно указанном файле `.mhv`: между шагами меняете значение
в программе и снова запускаете команду с этим файлом.

- **Условия**, по одному на шаг: `--eq N`, `--gt N`, `--lt N`, `--between A:B`, `--unknown` (только первый
  поиск), `--increased`, `--decreased`, `--changed`, `--unchanged` (только следующие, сравнение с прошлым шагом).
  - Целые числа могут быть отрицательными или в hex (`0x…`); `--eq` принимает и знаковый, и беззнаковый
    диапазон типа.
  - Для `float`/`double` `--eq` совпадает с точностью до половины последнего введённого знака
    (`100` — от 99.5 до 100.5).
- **Первый поиск:** тип `--as` (int8, int16, int32 по умолчанию, int64, float, double), `--unaligned`
  (проверять каждый байт, а не только кратные размеру), фильтры регионов как у `scan`.
- **Файл:**
  - Хранит процесс (PID и время создания), тип и адреса с последними значениями. Тип и адреса задаются
    первым поиском; `--as`, `--unaligned` и фильтры со следующим шагом дают код 2.
  - Следующий шаг заменяет файл, только если адреса остались. Если не осталось ни одного, файл не
    меняется (код 1). `--save NEW` пишет результат в новый файл, а исходный оставляет как есть.
  - Пишется как `FILE.partial` и переименовывается после записи; заголовок и данные защищены XXH64.
    Чужой, обрезанный, испорченный или более новый файл даёт понятную ошибку и код 6.
  - Если процесс перезапущен, файл отклоняется (код 6): адреса другого запуска ничего не значат.
    Если процесс завершился, команда выдаёт код 3.
- **Вывод:** адрес, значение, прошлое значение, защита, тип памяти и модуль; text, json или csv. По умолчанию
  первые 20 адресов, `--limit 0` выводит все. Без условия значения читаются из памяти сейчас.
- **Память:** список адресов первого поиска может занять не больше трети свободной RAM. Если он
  больше, например при `--unknown` по всей памяти, поиск останавливается с кодом 5 и советом сузить
  выборку. Ctrl+C тоже даёт код 5, и ничего не записывается.
- Значения только читаются: записи в память и заморозки нет.

### pointers: цепочки указателей

```sh
memhunter pointers game.exe --to 0x1F4A2C3B0D8 --save hp.mhp   # поиск цепочек к адресу здоровья
# перезапустите игру и найдите новый адрес, например memhunter value
memhunter pointers hp.mhp --to 0x2A61F0E1A48                   # оставить цепочки, ведущие к новому адресу
memhunter pointers hp.mhp --eq 100                             # или цепочки со значением 100 сейчас
memhunter pointers hp.mhp                                      # показать цепочки и куда они ведут сейчас
```

Цепочка `[[game.exe+0x1A2B0]+0x10]+0x8` читает указатель по адресу `game.exe+0x1A2B0`, прибавляет 0x10,
читает указатель там и прибавляет 0x8. Проверяйте после перезапусков, пока не останется несколько цепочек.

- **Поиск:** `--to ADDR` (десятичное или `0x…`), `--depth N` (1–7, по умолчанию 5), `--max-offset N`
  (по умолчанию 0x1000), `--max-chains N` (по умолчанию 1 000 000, остаются самые короткие), `--as TYPE` —
  тип значения для показа и для проверки по значению (int32 по умолчанию), `--save FILE`.
  - Указатели читаются из записываемой памяти всех типов; фильтры регионов как у `scan` это меняют.
  - Список цепочек и поиск могут занять не больше трети свободной RAM, иначе код 5 и совет уменьшить
    глубину или смещение.
- **Проверка:** первый аргумент — файл `.mhp`, второй (необязательный) — процесс. По умолчанию берётся
  процесс с тем же именем exe, что при сохранении. Условие — `--to ADDR` или `--eq`/`--gt`/`--lt`/`--between`
  (только для чисел). Файл заменяется, только если цепочки остались; `--save NEW` пишет в новый файл.
  `--depth`, `--max-offset`, `--max-chains`, `--as` и фильтры с файлом дают код 2. Файл 32-битного процесса
  не проверяется на 64-битном и наоборот (код 6).
- **Вывод:** база, смещения, адрес и значение сейчас; text, json или csv (`base,offsets,path,address,value`).
  По умолчанию первые 20 цепочек, `--limit 0` выводит все.
- Это тот же файл, что сохраняет и загружает GUI. Память только читается.

### struct: разбор структуры

```sh
memhunter struct game.exe 0x1F4A2C3B0D8                                  # поля структуры по адресу
memhunter struct game.exe "[[game.exe+0x52080]+0x8]" --def player.mhst   # по цепочке, с заданными полями
memhunter struct game.exe "[[game.exe+0x52080]+0x8]" --size 0x80 -f json
```

То же, что вкладка «Структура» в GUI, за один запуск: смещение, тип, имя и значение каждого поля.

- **База:** адрес или цепочка указателей к структуре, числа в hex. Цепочка проходится при каждом запуске,
  поэтому команда находит структуру и после перезапуска программы. На stderr выводится, куда цепочка ведёт
  сейчас (`[[game.exe+0x52080]+0x8] leads to 0x000001F4A2C3B000: 0x200 bytes, 52 fields`, `-q` это убирает).
- **Поля:** типы угадываются как в GUI (int64 не угадывается). `--def FILE` берёт поля из файла `.mhst`,
  который сохраняет GUI (`0x50 int32 health` по строке), а промежутки между ними угадывает. `--size N` —
  сколько байт показать, от 1 до 0x10000 (по умолчанию 0x200 или размер из файла).
- **Вывод:** text, json или csv (`offset,type,name,value`). Указатель в модуль показан как `game.exe+0x…`,
  нечитаемые байты — как `??`.
- Если цепочка сейчас никуда не ведёт или по адресу ничего не читается, код 1. Испорченный файл `.mhst` —
  код 6 с номером строки. Память только читается.

### tui: полноэкранный интерфейс

```sh
memhunter tui 1234 [-j N]
```

Нужна интерактивная консоль с поддержкой VT-последовательностей (Windows Terminal, conhost в Windows 10+)
размером не меньше 80×20. Если вывод перенаправлен, команда завершается с кодом 2 и советом использовать `scan`.

| Область | Что показывает |
|---|---|
| верхняя строка | MemHunter, PID, состояние поиска (с процентом), имя и разрядность процесса, кнопки Scan / Cancel / Save / Quit |
| поиск | строка для поиска, байтовая сигнатура, кодировка ASCII / UTF-16 / обе, регистр, тип памяти |
| прогресс | процент, прочитано байт, проверено регионов, найдено совпадений |
| результаты | адрес, вид совпадения, шаблон, длина, превью в тексте или hex; отметки `*` |
| детали | выбранное совпадение и его регион (адрес, размер, защита, тип, модуль); в нижней рамке подсказка по клавишам |
| строка статуса | скорость, ошибки чтения, время работы, сообщение |

- **Клавиши:**
  - Tab / Shift+Tab: переход между полями. Enter или F5: начать поиск. Esc: отменить поиск или ввод.
  - ↑ ↓ PgUp PgDn Home End: навигация по результатам. Space: отметить результат, `a`: отметить все или снять отметки.
  - `/`: фильтр по адресу, шаблону или тексту. `v` или F3: переключить hex/текст.
  - F2 или `s`: сохранить отмеченные результаты (или все показанные). Формат определяется по расширению:
    `.json`, `.csv`, иначе текст.
  - F10 или Ctrl+C: выход.
- **Поиск в фоне:** сканирование идёт в отдельном `std::jthread`, интерфейс не блокируется.
  - Прогресс передаётся через атомарные счётчики; результаты интерфейс забирает под мьютексом, когда
    поиск закончен.
  - Отмена срабатывает через `stop_token`, и выход тоже возможен во время поиска.
  - Изменение размера окна перерисовывает экран; если окно меньше 80×20, показывается сообщение.
- **Тема строго чёрно-белая.** В ней только три стиля:
  - обычный: белое на чёрном;
  - жирный белый: заголовки и подпись активного поля;
  - инверсия: выделение, фокус и курсор.

  Детали:
  - Фон `#000000`; текст, рамки и символы `#FFFFFF`. Цвета заданы явно в 24-битном виде, чтобы палитра
    терминала их не подкрашивала.
  - Панель в фокусе обводится двойной рамкой. Других цветов, градиентов, теней, эмодзи и анимаций нет.
  - Кнопки (`[Scan F5]`) выводятся белым на чёрном и инвертируются в фокусе; недоступная кнопка показывается
    без скобок. Поля ввода обведены белой рамкой, в них есть видимый курсор и читаемая подсказка.
  - Все цвета и стили собраны в `src/tui/theme.hpp`, отдельно от логики. Тест проверяет, что на экран
    выводятся только разрешённые последовательности SGR.
  - Обычные команды (`scan`, `diff` и другие) цвета не используют вообще.

## Коды выхода

| Код | Значение |
|---:|---|
| 0 | найдены совпадения, различия или команда выполнена |
| 1 | поиск завершён без совпадений, `diff` без различий, `value` без оставшихся адресов, `pointers` без цепочек (файл не меняется), у `struct` цепочка никуда не ведёт или память по адресу не читается |
| 2 | неверные аргументы или шаблон |
| 3 | процесс не найден, доступ запрещён или процесс завершился |
| 4 | ошибка файла (в том числе нехватка места) |
| 5 | поиск прерван или процесс завершился; частичные результаты выведены. У `value` и `pointers` также превышен бюджет памяти; ничего не записывается |
| 6 | снапшот, файл `.mhv`, `.mhp` или `.mhst` повреждён или несовместим; снапшот или `.mhv` снят с другого запуска процесса |
| 9 | внутренняя ошибка |

## Производительность

Замеры, условия и способ воспроизведения описаны в [bench/README.md](bench/README.md). Главное
(i5-14400F, 16 потоков, GCC 16.2.0, SSE2): 2 GiB памяти отдельного процесса и 10 сигнатур проверяются
за 0.16 с на свободной машине. Если рядом работает тяжёлая игра, это занимает 0.39–0.67 с (на одном
потоке 2.2 с). Требование «2 GB и 10 сигнатур за 3–5 с» выполнено с запасом. Под сильной посторонней
нагрузкой `--chunk-size 64K` был в 1.7 раза быстрее значения по умолчанию, а на свободной машине в 1.8 раза
медленнее, поэтому по умолчанию остаётся 256 KiB.

- Алгоритм выбирается по замерам:
  - До 20 шаблонов используется SIMD-поиск по якорным байтам (SSE2 со скалярной реализацией на случай,
    если SSE2 недоступен).
  - При большем числе шаблонов используется один проход Aho-Corasick.
  - Horspool и naive оставлены для сравнения и для шаблонов без надёжного якоря.
- `std::regex` в пути поиска не используется.

## Ограничения

- Снапшот не атомарен: процесс продолжает работать, пока снимается снапшот, а MemHunter намеренно его не
  приостанавливает.
- Сравнение без содержимого опирается на 64-битные хеши. Коллизия XXH64 теоретически может скрыть изменение.
- Если регион освободили и снова выделили по тому же адресу с тем же размером и защитой, это видно только
  как изменение содержимого, а не как пересоздание региона.
- Адреса имеют смысл только внутри одного запуска процесса, поэтому разные запуски по умолчанию не
  сравниваются (см. выше).
- `--changed-since` экономит время поиска, но не время чтения: вся выбранная память читается для хеширования.
  - Фильтр по умолчанию берёт память всех типов.
  - Память вне выборки базового снапшота считается `added`. Например, если снапшот снят с `--type private`,
    всё остальное при повторном поиске будет «новым». Лучше снимать снапшот и искать с одинаковыми фильтрами.
- В TUI и GUI результаты появляются, когда поиск закончен или отменён. Во время поиска видны только счётчики.
- TUI работает только в консоли с поддержкой VT размером не меньше 80×20.
- Следующий поиск значений есть в GUI и в `memhunter value`, в TUI его нет. История поисков с отменой шага
  есть только в GUI.
- Цепочки указателей начинаются только в образах модулей; базы на стеках потоков (`THREADSTACK` в Cheat
  Engine) не ищутся.
- Угадывание типов в структуре — подсказка, а не разбор кода программы:
  - int64 не угадывается и видно как два int32.
  - Текст угадывается только латиницей, греческим и кириллицей. UTF-16 на китайском, японском или корейском
    не угадывается: половинки float вроде 0.3 выглядят как такие символы. Такие поля задаются вручную.
  - Число перед текстом может прочитаться как начало строки; если первые 4 байта похожи на круглый float
    (`fff@` = 3.6), они считаются числом.
- Структура, как и всё остальное, только читается: значения полей не меняются и не замораживаются.
- Проверена только сборка MinGW-w64 GCC 16.2.0. Код рассчитан на MSVC, но там не собирался.
- Чтение 64-битных процессов требует 64-битной сборки MemHunter. 32-битные процессы (WOW64) читаются той же сборкой.
