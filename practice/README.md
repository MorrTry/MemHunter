# Тренировочная цель

`memhunter_practice.exe` — маленькая «игра» без графики, на которой удобно учиться работать с MemHunter.
Она хранит осмысленные данные (игрок, инвентарь, чат, сохранение, настройки) в разных видах памяти, меняет
их по нажатию клавиш и умеет включать три защиты.

Все защиты — обычные механизмы Windows, которые процесс применяет сам к себе. MemHunter их не обходит.
Упражнения показывают, как выглядит результат поиска, когда защита включена.

## Запуск

Собирается вместе с проектом (опция CMake `MEMHUNTER_BUILD_PRACTICE`, по умолчанию ON):
`build\release\practice\memhunter_practice.exe`. Зависит только от системных DLL.

Нужны два окна: в одном цель, в другом `memhunter`. Цель показывает свой PID и готовые команды с
подставленными PID, адресами и байтами. Экран рассчитан на окно 120×30 с подсказками и 120×22 без них.
В меньшем окне строки обрезаются, но ничего не прокручивается.

> Окно с `memhunter` лучше открывать как обычный пользователь, а не «от имени администратора». Проверка:
> `whoami /priv | findstr SeDebug`. Если привилегия включена (`Enabled` / `Включен`), Windows пропускает
> такой процесс мимо прав доступа, и защита [3] его не остановит. MemHunter эту привилегию сам не включает,
> но наследует её от окна, из которого запущен.

Если ввод и вывод перенаправлены, цель читает клавиши со стандартного ввода, а каждый экран печатает в UTF-8
и завершает строкой `----------------`. Конец ввода завершает программу. Так её можно гонять из скриптов.

## Клавиши

Русская раскладка тоже работает: используются те же физические клавиши.

| Клавиша | Действие |
|---|---|
| `d` / `в` | урон −13; если здоровье падает до нуля или ниже, игрок возрождается с полным здоровьем и теряет 10% денег |
| `e` / `у` | аптечка: +40 здоровья, аптечек становится на одну меньше |
| `m` / `ь` | +500 денег |
| `b` / `и` | купить аптечку за 350 |
| `w` / `ц` | шаг: x +1.5, z −0.75, опыт +120, игровое время +30 с |
| `c` / `с` | новое сообщение в чате (в памяти 8, на экране последние 4) |
| `r` / `к` | перенести состояние игрока на новые страницы памяти |
| `a` / `ф` | авто-режим: каждую секунду идёт игровое время, раз в 3 с +1 здоровья |
| `1`, `2`, `3` | включить или выключить защиту |
| `0` | снять все защиты |
| `i` / `ш` | показать или скрыть подсказки |
| `q` / `й`, `Esc` | выход |

## Что лежит в памяти

| Данные | Память | Защищены [1] и [2] |
|---|---|---|
| структура игрока `PLR1` | private, отдельные 64 KiB из `VirtualAlloc` | да |
| объект мира `WRLD` с указателем на игрока | private, куча | нет |
| указатель `g_world` на объект мира | image, секция данных exe | нет |
| сохранение `SAVEGAME v3 … location=Cordon …` | mapped, секция в файле подкачки | нет |
| настройки JSON с `eu-west-2.example.org` | private, куча (`std::string`) | нет |
| приветствие «Добро пожаловать в Зону! Сервер eu-west-2…» (UTF-16) | private, куча (`std::wstring`) | нет |
| тексты интерфейса («Клавиши: …», UTF-16) | image, секция данных exe | нет |

Тексты игрока (имя, звание, предметы, чат, `PLR1`) и начальные числа хранятся в exe в закодированном виде.
Поэтому при включённом шифровании их не находит даже `--type image`.

Структура игрока (64-битная сборка, little-endian):

| Смещение | Поле | Тип | Начальное значение |
|---:|---|---|---|
| +0x00 | метка | char[4] | `PLR1` = `50 4C 52 31` |
| +0x04 | версия | uint32 | 1 |
| +0x08 | имя | char[24] | `Stalker_Ivan` |
| +0x20 | звание | wchar_t[24] | `Вольный сталкер` |
| +0x50 | здоровье | int32 | 86 |
| +0x54 | максимум здоровья | int32 | 100 |
| +0x58 | деньги | int32 | 15000 = `98 3A 00 00` |
| +0x5C | уровень | int32 | 7 |
| +0x60 | опыт | int64 | 64200 |
| +0x68 | позиция x, y, z | float ×3 | 102.5, 4.0, −37.25 |
| +0x74 | броня | float | 35.0 |
| +0x78 | игровое время, с | uint32 | 29100 (08:05:00) |
| +0x7C | число предметов | uint32 | 7 |
| +0x80 | предметы | 16 × 0x20 | id +0x00 (uint32), количество +0x04 (uint16), состояние % +0x06 (uint16), вес +0x08 (float), название +0x0C (char[20]) |
| +0x280 | число сообщений | uint32 | 2 |
| +0x284 | чат | 8 × 0x80 | минута +0x00 (uint32), текст +0x04 (wchar_t[62]) |

Объект мира: `WRLD` +0x00, число игроков +0x04 (uint32, 1), указатель на структуру игрока +0x08 (8 байт),
локация `Кордон` +0x10 (wchar_t[16]).

Смещения проверяются `static_assert` в исходнике, так что таблица не разойдётся с кодом.

## Упражнения

Ниже `PID` — номер процесса из первой строки экрана цели.

1. **Найти процесс.** `memhunter ps memhunter_practice*`. Посмотрите регионы: `memhunter regions PID`,
   затем `--type mapped`, затем `--all` (там видны и зарезервированные, и недоступные регионы).
2. **ASCII-строка.** `memhunter scan PID -s Stalker_Ivan`. Найдётся одно совпадение по адресу «база + 0x8»
   в private-регионе размером 64 KiB. В превью после имени видны нули и начало звания в UTF-16.
3. **UTF-16 с кириллицей.** `memhunter scan PID -s "Вольный сталкер" --unicode`. Совпадение находится по
   адресу «база + 0x20». Без `--unicode` поиск идёт сразу в обеих кодировках.
4. **Число.** Деньги 15000 = 0x3A98, в памяти это `98 3A 00 00`: `memhunter scan PID -p "money=98 3A 00 00"`.
   В превью видно, что дальше идут уровень `07 00 00 00` и опыт `C8 FA 00 00 …` (64200). Нажмите `m`, и
   денег станет 15500 = `8C 3C 00 00`. Старое значение больше не находится, новое лежит по тому же адресу.
   Короткие числа часто встречаются в памяти случайно. Отсеивать лишнее помогает сравнение «до» и «после».
5. **Снапшот и сравнение.** `memhunter snapshot PID -o a.mhs`, затем `m`, затем `memhunter diff PID a.mhs`.
   В списке изменённых блоков будет страница структуры игрока. После этого
   `memhunter scan PID -p "8C 3C 00 00" --changed-since a.mhs` ищет только в изменившейся памяти.
6. **Структура целиком.** `memhunter scan PID -p "PLR1=50 4C 52 31"` даёт адрес начала структуры. Сравните
   превью с таблицей смещений. В `memhunter tui PID` выберите совпадение: в панели Details байты видны
   с относительными смещениями.
7. **Указатель и маска.** Объект мира хранит адрес структуры игрока. Найдите его по сигнатуре с `??`:
   `memhunter scan PID -p "world=57 52 4C 44 01 00 00 00 ?? ?? ?? ?? ?? ?? 00 00"`. Последние 8 байт
   превью — это адрес из упражнения 6 в little-endian. Нажмите `r`: структура переедет на новые страницы,
   `PLR1` найдётся по новому адресу, а указатель в `WRLD` обновится.
8. **Типы памяти.** `memhunter scan PID -s Cordon --type mapped` находит сохранение, а с `--type private`
   ничего не находит. `memhunter scan PID -s eu-west-2 --type private` находит две копии: ASCII в
   настройках и UTF-16 в приветствии. `memhunter scan PID -s Клавиши --unicode --type image` находит текст
   интерфейса в exe. `memhunter scan PID -s Stalker_Ivan --type image` ничего не находит.
9. **Извлечение строк.** `memhunter scan PID --strings --min-length 8 --type mapped --grep SAVEGAME`.
10. **Цепочка указателей.** Адрес здоровья меняется при каждом запуске и после `r`, а путь к нему от exe
    остаётся тем же.
    - Найдите здоровье: `memhunter value PID --eq 86 --save hp.mhv`, нажмите `d`, затем
      `memhunter value hp.mhv --eq 73`. Останется один адрес.
    - `memhunter pointers PID --to АДРЕС --save hp.mhp` найдёт несколько тысяч цепочек.
    - Закройте цель и запустите её снова. Найдите здоровье ещё раз и выполните
      `memhunter pointers hp.mhp --to НОВЫЙ_АДРЕС`. Останется
      `[[memhunter_practice.exe+0x…]+0x8]+0x50`: глобальный указатель `g_world` → указатель на игрока в
      `WRLD` (+0x08) → здоровье (+0x50).
    - Нажмите `r`: `memhunter pointers hp.mhp` покажет новый адрес и то же значение.
    - В GUI то же самое: на вкладке «Адреса» выберите здоровье → «Найти указатели…». После перезапуска
      выберите новый процесс и нажмите «Проверить…» на вкладке «Указатели», затем «В список адресов».
      Эта запись идёт за структурой после `r` и после перезапуска.
    - С защитой [2] адрес по цепочке вычисляется, но значение показано как `??`. С [1] вместо значения
      видны случайные числа.

## Защиты

**[1] Шифрование.** Структура игрока хранится под XOR с потоком xorshift64\*. Ключ меняется при каждой
записи: при нажатии клавиши, а в авто-режиме раз в секунду. Расшифрованная копия появляется только в
стеке на время чтения или изменения и сразу затирается. Экран собирается в отдельном буфере, который тоже
затирается после вывода.

- `-s Stalker_Ivan`, `-s "Вольный сталкер"`, `-p "50 4C 52 31"`, `-s Medkit`, `-s Сидорович` дают код 1,
  то есть ничего не найдено. Незащищённые данные (`WRLD`, `Cordon`, `eu-west-2`) находятся как раньше.
- Указатель из `WRLD` всё ещё ведёт к структуре. По этому адресу видны случайные байты, которые меняются
  после каждой клавиши. Это хорошо заметно через `snapshot` и `diff`.
- Ограничение, которое важно понимать: ключ и код расшифровки находятся в том же процессе. Такая защита
  только прячет открытый текст от поиска. MemHunter не пытается её расшифровать.

**[2] Закрытые страницы.** Между обращениями 64 KiB структуры имеют защиту `PAGE_NOACCESS`. На время
чтения или записи программа открывает их сама.

- `memhunter regions PID --all --type private` показывает этот регион с защитой `---`. Обычный
  `memhunter regions PID` его не показывает.
- `memhunter scan PID -s Stalker_Ivan` даёт код 1: поиск пропускает недоступные страницы и guard-страницы.
  MemHunter не меняет защиту страниц чужого процесса (`VirtualProtectEx` не используется).

**[3] Запрет открытия процесса.** Цель заменяет свой DACL. Пользователю остаются только
`PROCESS_QUERY_LIMITED_INFORMATION`, `SYNCHRONIZE`, `PROCESS_TERMINATE` и `READ_CONTROL`, системе остаётся
полный доступ.

- `memhunter scan PID …` и `memhunter regions PID` завершаются с кодом 3 и сообщением об отказе в доступе.
- `memhunter ps` по-прежнему показывает процесс, а диспетчер задач может его завершить.
- Windows проверяет права, когда открывается дескриптор. Поэтому `memhunter tui PID`, запущенный до
  нажатия `3`, продолжает искать: его дескриптор уже открыт.
- Владелец процесса может вернуть DACL обратно: право `WRITE_DAC` у владельца есть всегда. Процесс с
  включённой `SeDebugPrivilege` (см. «Запуск») проходит и без этого. MemHunter не делает ни того, ни другого.

`0` снимает все три защиты сразу. Защиты можно включать вместе. Например, с [1] и [2] данные одновременно
зашифрованы и закрыты.
